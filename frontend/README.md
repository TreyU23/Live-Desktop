# Frontend

React 19/Vite 6 renders seven views with [Astryx](https://github.com/meta/astryx) components (`@astryxdesign/core` and `theme-neutral` 0.7.16, pinned). `App.jsx` owns APIs, profiles and mutations; `src/views/` and `src/components/` own presentation. There is no project stylesheet: `main.jsx` imports Astryx's `reset.css` and `astryx.css`, and `src/astryx-themes.js` (generated by `astryx theme add`) brings in the five local themes. Theme sources live in `themes/<slug>/`. Conventions are in [AGENTS.md](AGENTS.md); run the CLI as `pnpm exec astryx <command>`. [Root setup/accounts](../README.md), [design contract](../DESIGN.md).

## Development and build

From the repository root, with Node 20.19+ or 22.12+ and pnpm:

```powershell
pnpm --dir frontend install --frozen-lockfile
.\scripts\run-frontend.ps1
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:sites
pnpm --dir frontend exec astryx doctor --built dist/client
```

The script can use Codex's bundled Node/pnpm and starts loopback Vite on strict port 4173, proxying `/api` and `/health` to 4317. The dev proxy rewrites `Host` to the backend so the backend allowlist matches the accepting port. `vite.config.mjs` binds to `127.0.0.1` unless `VITE_HOST` is set, and uses Vite's default host check (no extra `allowedHosts`), so the dev server answers only to `localhost` and IP-address hosts. Vite is pinned at 6.4.6. Vite and `@vitejs/plugin-react` are `devDependencies` (build-time only), so `pnpm audit --prod` covers only the runtime packages; run plain `pnpm audit` to include the build toolchain. `App.jsx` reads `X-Live-Desktop-Token` from a loopback `GET /health` and sends it on later calls. `POST` and `DELETE` send `Content-Type: application/json`. `VITE_API_BASE` overrides the API at build/development time; a loopback override on port 4173 or the backend port can read the token header. When `VITE_HOST` exposes the dev server beyond loopback, every proxied call reaches the backend from `127.0.0.1`, so the proxy itself removes `X-Live-Desktop-Token` from `/health` responses to non-loopback callers.

Production serves `dist/client/` through the native host without Node. The build injects a Content Security Policy `<meta>` into `index.html` (`kContentSecurityPolicy` in `vite.config.mjs`; the dev server has none because React refresh needs inline scripts). It allows scripts and styles from the app's own origin, inline style attributes, hashes for the two static stylesheets Astryx injects (Layer and CodeBlock, valid for the pinned 0.7.16), and frames from `embed.music.apple.com` and `open.spotify.com` only. Saved music links are re-checked against the same provider allowlist when they load from `localStorage` (`migrateMusicIntegration`), so a tampered link falls back to the default instead of becoming the iframe `src`, in dev builds too. After an Astryx upgrade, `tests/browser-redesign.mjs` reports any new violation; update the hashes from the console message. The build also emits `dist/server/index.js` and `dist/.openai/hosting.json`; preserve `.openai/hosting.json`, `worker/index.js`, the preparation script and Sites tests. A hosted preview needs its own backend integration for local Windows features.

## State and refresh contracts

`resourceScheduler.js` commits resources independently, permits one read per resource and applies a 12-second deadline. Reads capture profile identity; teardown aborts them. Mutations invalidate reads before and after writes so older responses cannot overwrite confirmed results. Manual refresh joins existing reads. Healthy scheduling stays in refs; visible state tracks loading, errors/recovery and freshness. Failures retain last-known data with retry; successful empty lists remain empty; missing readings show a dash.

| Resource | Interval after completion |
| --- | --- |
| Media | 5 seconds |
| Phone Link | 10 seconds |
| System | 15 seconds |
| Health/runtime | 30 seconds |
| Apps/actions/memories/conversations/settings | 60 seconds |
| Calendar | 4 minutes |

Hidden documents pause routine reads; visibility restoration triggers deduplicated refreshes. Profile switching stops old reads and reloads; request headers/browser preferences retain profile identity. Failed assistant/memory submissions preserve drafts. Successful saves clear drafts even if list refresh fails.

The selected music embed (`components/media/MusicFrame.jsx`) mounts on first Music visit and persists across navigation: on other views it is parked (clipped, `inert`, hidden from assistive tech), never unmounted; provider switches replace it. It carries a `sandbox` attribute (scripts, same-origin, popups, presentation, storage access). Metadata comes from Windows sessions. Phone artwork reflects available platform metadata. Unsupported controls open Windows Settings and say so; direct radio switches request a change that runs only after approval and show confirmed state. Voice input/calendar editing are not implemented.

`AppShell` holds the side navigation (a drawer below 768 px) and the content column; every view renders through `components/shell/Page.jsx`, which places the shared local-status and Restart/Stop Live Desktop actions beside the title. Appearance (Light/Dark/System) and the accent preset are profile scoped; an accent is a built theme selected through `<Theme>`, and `accentColors.js` only maps a hex saved by the old glass UI to the nearest preset. The SVG gauge and sparkline in `components/instruments/` are the only hand-drawn UI and use theme tokens. A pending action that appears while Conversations is open raises the approval `Dialog`; the Approvals view keeps the full queue and history with inline decisions. Stop/profile-deletion confirmations are `AlertDialog`s (focus contained, Escape cancels, focus restored).

[Validation commands/limits](../docs/VALIDATION.md) cover browser rendering, polling, mutation races, production smoke and diagnostics. Synthetic browser evidence goes under ignored `backend/target/`.
